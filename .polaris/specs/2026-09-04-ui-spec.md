# quickgist UI spec (slice 2)

Date: 2026-09-04
Status: approved, ready for a plan

## What this covers

The whole user-facing interface, designed from scratch. Slice 1 rebuilt every layer below it:
Supabase Postgres with authorization in the database, Supabase Auth, server-side Markdown and code
rendering, and a plain React shell that exercises the endpoints. That shell is replaced here.

One backend addition is in scope, because the interface depends on it: `POST /v1/preview`.

## Product

Someone reaches for quickgist instead of hunting for a tool. They paste Markdown or code, get a
link, and send it. The person receiving the link reads a properly rendered document.

Two jobs, pulling in different directions. Composing wants density and speed. Reading wants a
comfortable measure. The design resolves this by keeping editor chrome throughout and giving the
document a reading measure inside it, rather than switching design languages between the two.

## Decisions settled

| Decision | Choice | Why |
|---|---|---|
| Landing route | The editor itself | The tool is the front door. Browsing and search get their own route. |
| Live preview | Yes, server-rendered via `POST /v1/preview` | Preview must be byte-identical to the published page. A client-side renderer would diverge, which is worse than no preview because it lies. |
| Preview layout | Toggle, not permanent split | `⌘⇧P` swaps the pane. A permanent split halves the writing width on a laptop. |
| Visual direction | Editor-native, following Zed | Chosen over an editorial or hybrid direction. |
| Light theme | Both themes | The renderer already emits both syntax palettes. |
| Link confirmation | A dismissible band above the rendered gist | It answers the question you have at that second: here is the link, and below it, proof the table survived. A full page makes you click through to find out, and it is a route that exists once in a gist's life. |
| Client state | React Query plus `useReducer`, no Zustand | Server state is already React Query's. The only client state is the editor draft, confined to one route. Zustand earns its place if drafts must survive navigation. |
| Attribution | Zed credited in the footer | Named as an acknowledgement, not buried in fine print. |

## Visual system

Zed's language, reduced to rules that can be applied consistently.

### The restraint that makes it work

Exactly **two** blue surfaces exist in the product: the link-ready band and the footer. They never
share a screen, because the band is at the top of a gist and the footer is the end of the page.
Everywhere else, hairline borders and greys do the work colour usually does. A third blue field
would cost the other two their meaning.

### Typography

Three faces, each with one job. IBM Plex, because Zed Plex is IBM Plex.

| Face | Used for | Weights |
|---|---|---|
| IBM Plex Sans | UI chrome and prose | 400, 500, 600 |
| IBM Plex Mono | Code, filenames, slugs, URLs, keyboard badges | 400, 500 |
| IBM Plex Serif italic | One display line on the home route, nothing else | 300 italic |

Self-hosted through `@fontsource`, latin subset, woff2 only. Not Google Fonts: a third-party
request on every page load is a privacy cost and a render-blocking dependency, and this app shows
private documents.

Prose sits on a **62-character measure** at 12.5px/1.72. Mono is 11px in blocks. UI chrome is
11 to 12.5px. Labels are 9.5px uppercase with 0.07 to 0.13em tracking.

### Colour tokens

CSS custom properties on `:root`, redefined under the dark conditions below.

Dark:

```
--bg #0d0f13   --panel #16181d   --panel-2 #1b1e24
--border #24272e   --border-strong #2f333c
--heading #eceef2   --text #d6d9df   --body #b9bec7   --dim #8b909a   --faint #585d67
--grid rgba(255,255,255,.022)
```

Light, Zed's One Light family rather than an inverted dark:

```
--bg #fafafa   --panel #f2f2f3   --panel-2 #eeeef0
--border #e2e2e4   --border-strong #d0d0d3
--heading #22242b   --text #383a41   --body #4a4c53   --dim #7c7f88   --faint #a2a3a7
--grid rgba(0,0,0,.028)
```

Shared, identical in both themes:

```
--blue-field  #1d4ed8    the two full surfaces
--blue-action #3b82f6    the primary button, the active tab underline, the blockquote rule
```

### Texture

Three signatures carried from Zed, all CSS-only.

- **Blueprint grid.** Two `repeating-linear-gradient` hairlines at 26px on `--grid`. On a blue field
  the same grid runs at `rgba(255,255,255,.07)`.
- **Corner crosshairs.** 7px tick marks at each corner of a framed surface, in `--border-strong`.
- **Outlined wordmark.** On a blue field only: "quickgist" at weight 600, transparent fill, 1px
  white stroke at 13% opacity, bled off the bottom-right corner.

### Theme resolution

Three states, because there are three. The Go renderer already handles this for syntax CSS and the
app CSS must match it:

1. `[data-theme="dark"]` on the root wins.
2. `[data-theme="light"]` on the root wins.
3. Neither present, the default: `@media (prefers-color-scheme: dark)` guarded by
   `:root:not([data-theme="light"])`.

The choice persists in `localStorage`, read by a blocking inline script in `index.html` so the first
paint is never the wrong theme.

## Backend changes

### Syntax palette

The renderer currently uses chroma's `github` and `github-dark`. Zed's palette is One Dark and One
Light. Chroma ships `onedark` and has no One Light, so:

- dark: chroma's `onedark`
- light: a style registered at startup with `chroma.MustNewStyle` and `styles.Register`, using One
  Light's values (keyword `#a626a4`, string `#50a14f`, function `#4078f2`, comment `#a0a1a7`
  italic, number `#986801`, type `#c18401`, foreground `#383a41`, background `#fafafa`)

`rendererVersion` bumps from `r1` to `r2`, invalidating every cached render. That is the mechanism
working as designed and needs no migration.

### `POST /v1/preview`

Renders content without storing it, so the editor's preview and the published page come from one
pipeline.

```
POST /v1/preview
Content-Type: application/json

{ "filename": "RUNBOOK.md", "language": null, "content": "# hi" }

200 { "kind": "markdown", "html": "<h1 id=\"hi\">hi</h1>" }
```

Constraints, each reusing what the create path already expresses rather than restating it:

- Body capped at the same 1 MiB text limit as `gist_files.content`.
- Anonymous callers allowed, matching create.
- Its own rate limit, stricter than the default, because it is called on a debounce while typing.
  A typist must not be able to exhaust their budget for reading.
- No database access at all, so it cannot become a write path.
- Same sanitizer, same renderer instance, same `Hash()`.

## Routes

| Route | Purpose | Auth |
|---|---|---|
| `/` | The editor. Creating lands on `/g/:slug` with the band shown. | anonymous fine |
| `/g/:slug` | The rendered gist, tabbed by file | anonymous fine |
| `/g/:slug/edit` | The editor loaded with an existing gist | author |
| `/explore` | Public feed and full-text search | anonymous fine |
| `/u/:handle` | One author's gists | anonymous fine |
| `/me` | Your own gists, including unlisted and private | required |
| `*` | Not found, in the same chrome | — |

Deliberately absent: a settings page, a profile editor, and a landing page separate from the editor.
Publish settings live in the editor's status bar and the link band.

## Component boundaries

Per the repository's TypeScript conventions: types in dedicated `types.ts` files, no barrel exports,
kebab-case utilities, PascalCase components, explicit return types on exports.

```

  types.ts                   extended with view and editor types
  schemas.ts                 extended with the preview response
  theme/
    theme-context.ts         the three-state resolver
    ThemeProvider.tsx
    use-theme.ts
  chrome/
    AppFrame.tsx             grid, crosshairs, chrome bar, footer
    ChromeBar.tsx            brand, actions, keyboard badges
    FileTabs.tsx             shared by editor and gist view
    StatusBar.tsx            slot-based, both routes fill it differently
    KeyboardBadge.tsx
    Footer.tsx               includes the Zed credit
  editor/
    editor-reducer.ts        the multi-file draft: add, rename, edit, remove, switch
    types.ts
    EditorRoute.tsx
    SourcePane.tsx           textarea with a line gutter
    PreviewPane.tsx          consumes use-preview

    use-draft-persistence.ts localStorage, so a reload does not lose the paste
  gist/
    GistRoute.tsx
    RenderedFile.tsx         injects server HTML
    BinaryFile.tsx           upload, size, expiry

  explore/

    SearchField.tsx
```

`StatusBar` takes slots rather than knowing about gists or drafts, so the editor and the gist view
can both use it without either leaking into it.

## Keyboard map

The chrome shows each binding beside its action, so the map is discoverable without a cheatsheet.

| Key | Action | Where |
|---|---|---|
| `⌘K` | Command palette | everywhere |
| `⌘↵` | Create the gist | editor |
| `⌘⇧P` | Toggle preview | editor |
| `⌘S` | Save an edit | editor on an existing gist |
| `⌘C` | Copy the link | gist, while the band is up |
| `N` | New gist | gist, explore |
| `E` | Edit | gist, if you are the author |
| `1` to `9` | Switch to file n | editor, gist |
| `/` | Focus search | explore |
| `?` | Shortcut list | everywhere |

Single-letter bindings are suppressed while focus is in a text field, using a focus guard rather
than a list of every input.

## React 19 and 19.2 features, and where each is used

Each one replaces code rather than being added for its own sake.

| Feature | Where | What it replaces |
|---|---|---|
| Document metadata | `GistRoute` renders `<title>`, `<meta name="description">`, `og:title`, `og:description` | `react-helmet`. Without it every shared link previews as a blank card, which for a sharing tool is the highest-value item here. |
| `<link rel="stylesheet" precedence>` | `AppFrame` links the API's `highlight.css` | Deletes `src/lib/highlight-stylesheet.ts` and its imperative DOM code. |
| `<form action>` and `useActionState` | Create and edit | Manual `onSubmit`, `isPending` and error state. |
| `useFormStatus` | The submit button inside the form | Prop-drilling pending state. |
| `useOptimistic` | Title rename, adding a file | Manual optimistic state. |
| `<Activity mode="hidden">` | The pane the preview toggle is not showing | Keeps scroll position and preview state alive across toggles instead of remounting. |
| `useEffectEvent` | `SessionProvider`'s auth listener, the keyboard handler | Effects that re-subscribe whenever a callback identity changes. |
| `ref` as a prop | Editor textarea, search field | `forwardRef`. |
| Context as provider | `ThemeProvider`, already the pattern in `SessionProvider` | `<Context.Provider>`. |

`use()` is deliberately unused. React Query already owns async reads, and a second suspense path for
the same data would be two ways to do one thing.

## States that must be designed, not discovered

Each gets a defined appearance in both themes:

- **Editor empty.** The paste box with a placeholder, not a zero-state illustration.
- **Preview pending.** The previous render stays visible with an activity mark in the pane header.
  It does not blank, because blanking on every keystroke pause is worse than slightly stale.
- **Preview failed.** The pane keeps the last good render and the header says the preview is stale.
  A preview failure never blocks the source.
- **Gist loading.** Chrome and tabs render immediately; only the document area waits.
- **Gist not found.** One line, in chrome, offering a new gist. A private gist and a missing one are
  indistinguishable here, matching the API's 404.
- **Expired upload.** The file tab stays, and the pane says when it expired and that the text files
  are intact.
- **Explore empty.** Distinguishes "no public gists yet" from "nothing matches that search".
- **Offline or API down.** The chrome stays; a band states the API is unreachable.
- **Rate limited.** The 429's `Retry-After` becomes a countdown rather than a generic error.

## Accessibility

- The file tabs are a real tab pattern: `role="tablist"`, arrow-key navigation, `aria-selected`.
- The preview toggle is a pressed button, not a styled div.
- Rendered gist HTML is server-sanitized and lands in a `<main>` landmark, with the heading
  hierarchy starting at the `h1` the document itself provides.
- The band is an `aria-live="polite"` region so its arrival is announced.
- Hairline borders carry structure, so each is paired with a non-colour cue: the active tab has an
  underline, not only a lighter panel.
- Contrast is checked against WCAG AA for body text in both themes. `--faint` on `--bg` is the risky
  pair and is restricted to decorative labels that repeat information available elsewhere.
- Everything is operable without a pointer, and `?` lists the map.

## Testing

- `editor-reducer.ts` gets table-driven tests: add, rename to a duplicate name, remove the last
  file, switch to a removed index.
- `use-preview.ts` gets a test that it debounces and that a failure keeps the last good HTML.
- The theme resolver gets a test for all three states.
- `POST /v1/preview` gets Go table-driven tests for the size cap, an unknown language, and that it
  never touches the database.
- One end-to-end pass in Chrome: paste, toggle preview, create, copy, open the link in a fresh
  session, switch theme, upload a file.

## Out of scope

Named so they do not creep in: comments, stars, forks, gist versioning, folders, teams, custom
domains, syntax highlighting inside the textarea, and collaborative editing. "Fork" appeared in an
early mockup and is cut; it needs a data model this schema does not have.

## Risks

- **The preview endpoint is new unauthenticated compute.** Rendering is CPU-bound and a 1 MiB
  Markdown document is not cheap. Its own stricter rate limit and the existing body cap mitigate
  this, but it is the only new attack surface in this slice and deserves a load check before it
  ships.
- **Three self-hosted font families is real weight.** Held to the six files actually used, latin
  subset. If the total passes roughly 150 KB, the serif italic is the one to cut, since it appears on
  one line of one route.
- **The `rendererVersion` bump invalidates every cached render at once.** Harmless now, with almost
  no data. Worth remembering before doing it again on a populated database, where every gist
  re-renders on its next view.
